# v4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (Native, elegido por el usuario en v1–v3).

**Goal:** mini-carrito vivo, popup con pestañas, PDP/carrusel con caja, promos NxM automáticas.

**Architecture:** igual que v3: intermediario MAIN (`src/interceptor.js`) lee y ajusta XHR; parte
aislada (`badge.js`, `cart-ui.js`, nuevo `promo-ui.js`) dibuja; `bridge.js` pasa ajustes.

**Tech Stack:** JS ESM, esbuild, Vitest + jsdom, Chrome MV3.

**Spec:** `docs/superpowers/specs/2026-11-09-v4-carrito-popup-pdp-promos-design.md`

## Global Constraints

- No romper nada nativo de Coto; solo agregar nodos y atributos `data-coto-unit-*`.
- Escrituras al DOM con guardas de igualdad (evita bucles del MutationObserver).
- Textos en español rioplatense, cortos.
- Ajustes nuevos: `autoPromo`, `notifyPromo`, `markBest` (default `true`), `popupTab`.

## Review Focus

1. Reescritura NxM con clics rápidos antes de que llegue `getCarrito` (cantidad anterior vieja).
2. Producto sin datos conocidos al agregar: la espera por PLU no debe colgar el carrito (tope 1,5 s).
3. Bajar cantidad o borrar (quantity 0 / negativa) nunca se reescribe.
4. Body no JSON o de otra forma: se envía tal cual.
5. Carrusel reusado por Swiper (slides duplicados): caja por tarjeta, sin duplicar.

---

### Task 1: Regla NxM (`src/promo.js`)
- `parseNxM(data) → {n, m} | null` desde `discounts[].discountText` (`/^\s*(\d+)\s*x\s*(\d+)\s*$/i`, n > m ≥ 1).
- `adjustQty(prev, next, nxm) → number`: si `next > prev` y `next % n === m` → `next + n − m`; si no, `next`.
- `promoNotice(data, qty) → string | null`: "3x2: llevando 3 pagás 2" cuando NxM no completo;
  textos de "70% 2da" / "Llevando N" para el resto; null sin promo.
- Tests: `tests/promo.test.js` (2x1 0→1→2, 2→3→4; 3x2 0→1 queda 1, 1→2→3; 6x4 3→4→6; bajar 2→1 queda 1).

### Task 2: Intermediario
- `cartWanted` (spec §1), sin `FORCE_CART_MS`.
- Índice `byProd: Map(prodId → data)` desde productos, recomendaciones y búsquedas por PLU.
- `send` parcheado para POST `addOrRemoveItemToOrderV2`: reescribe `quantity` (spec §4), guarda
  `sentQty[prodId]`, publica `promoAdjust` / `promoNotice`. Respeta `settings.autoPromo/notifyPromo`.
- Tests en `tests/interceptor.test.js` (FakeXHR con `send(body)`).

### Task 3: Etiquetas por `data.id` y metros desde m²
- `labelsFor` agrega la clave `data.id` además de `data.url`.
- `measure()`: papel higiénico con formato m² sin metros en el nombre → `rollo10m`,
  divisor = m² × 10 / 10 (= m²), nota "≈ ancho 10 cm".
- Tests: `tests/units-v3.test.js` / `tests/sort.test.js`.

### Task 4: PDP, carrusel, aviso
- PDP: caja después del bloque de precio (spec §3) + atenuar líneas secundarias.
- Carrusel `mini-product-card` por `data-cnstrc-item-id`, caja compacta.
- `markBest` apaga el "Más barato".
- `src/promo-ui.js`: escucha `promoAdjust` (pone el número visible) y `promoNotice` (aviso breve).
- Tests: `tests/badge.test.js`, `tests/promo-ui.test.js`.

### Task 5: Popup
- `popup.html`, `src/popup.js`, `src/popup.css`, `assets/fonts/poppins-*.woff2` (OFL).
- Pestañas Tarjetas / Ajustes / Ayuda; ajustes a storage; bridge envía flags.
- Tests: `tests/popup.test.js` (pestañas recuerdan, buscador filtra, interruptores guardan).

### Task 6: Verificación en vivo
- Sesión iniciada en el navegador de la app; 2x1 y 3x2 reales; mini-carrito; PDP; carrusel; popup.
